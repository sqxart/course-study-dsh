# 多账号运行（实验性）

同一台机器上放多个学习通账号时看这份说明。默认用法仍是单账号；多账号只改变“通道和执行器怎么分配”，
不改变授权、证据和停手规则。跨账号并发仅有有限范围的验证；
长视频、测验/提交并发仍未验证，不要扩大成“并发已通过”。

## 拓扑

通用规则：**N 个账号 = N 条 `mcp-client` 条目 = N 个独立 `--user-data-dir` = N 个标签 = N 个执行器**。
配置示例（不表示本机已登录状态）：

| 通道 | 工具前缀 | profile | 截图/快照目录 |
|---|---|---|---|
| `browser` | `mcp__browser__*` | `~/.dsh/browser/profile-1` | `~/.dsh/browser/output-1` |
| `browser2` | `mcp__browser2__*` | `~/.dsh/browser/profile-2` | `~/.dsh/browser/output-2` |
| `browser3` | `mcp__browser3__*` | `~/.dsh/browser/profile-3` | `~/.dsh/browser/output-3` |

- 条目 id 必须不同（`mcp-browser` / `mcp-browser2` / `mcp-browser3`）；同 id 会覆盖前一条。新增第 N 个账号就复制一份，
  只改 `id`、`serverName`、`--user-data-dir`、`--output-dir` 四处；配置形状见 [DSH 运行说明](dsh-runtime.md) 的「启用受支持的浏览器通道」。
- **不要复用退役账号的 profile**：退役 profile 里可能还有旧账号的 cookie，会把新账号登成旧账号。用全新 profile
  登录新账号后，页面显示的是新账号本人，没有串号。
- 两个账号不能共用一个 `--user-data-dir`：登录态会互相踩，平台也会看到同一个浏览器里的两个会话。
- `--output-dir` 也不同：`browser_take_screenshot` 的 `filename` 落在各自目录，按所属通道保留截图来源。

## 规则

- **一个账号同一时间只有一个执行器、一个标签**。两个账号各由一个执行器操作时，各自仍按单账号红线：跳页间隔 ≥4 秒、每轮 ≤10 跳、不拼 `studentstudy`/`cards` 直链。
- 账号之间不共享标签、执行器、登录态；不把一个账号的 cookie 或答案搬给另一个账号。字幕按课程复用，但记录里写清来源账号。
- 跨账号并发只在“可中断的边界”发生：一个账号不在提交、不在计时测验、不在答题页时，另一个账号才开工。先只读动作，再考虑长节点。
- 成本分开算：每个账号的节点用各自的子 agent 会话跑 `session_cost.py`，不要合成一个数；`evidence.json` 的 `account_alias` 必填（见 [本地状态与交接](state.md)）。
- **任一账号出现验证码、9010、多终端登录提醒或日上限（`.maskDiv.jobCountDiv` 几何尺寸 > 0）→ 两个都停**，保留两侧现场（标签、截图、evidence），不重试、不换通道重试、不删痕迹。
- 登录态不保证跨重启保持；重新登录由用户完成或用户明确授权时由 Agent 代输一次，密码不写入任何文件、不回显。
- 新增一条通道会重载 MCP，但不必重启 harness：在 `insert` 里加一条 `mcp-browser3` 后，当前会话的工具面直接出现 `mcp__browser3__*`（25 个工具）。仍只在节点边界改配置。
- 登录页的“下次自动登录”勾选与平台会话策略由平台决定，不在技能控制范围；不要在未确认时声称登录已保持。

## 配置限制

`local/private.toml` 是**本机一份**，所有账号共用：要一个账号 `completion`、另一个 `evidence`，本版做不到按账号分开。
只能分两次跑，并在每次的 `evidence.json` 里写明本次 `mode`；不要同时用两种模式跑两个账号。
多账号视频并发可以都按 `evidence`（不提交）跑；要提交时先确认**每个账号各自**的授权，不能把一个账号的授权用于另一个账号。

## 验证范围与限制

- 有界视频并发采用独立账号、独立通道、每节点一个子 agent 和单标签串行链；仍按每个账号的授权、证据与停止条件执行。
- 只读验收核对各通道页面归属、官方播放速率、平台任务点变化和 `--audit-submit`，不通过切换通道绕过异常。
- 长视频同时播放、测验并发、提交并发和同账号多标签稳定性未充分验证；有限实验不能扩大为普遍通过。
- 逐账号、逐节点的结果与成本只留在本地 `runs/`，公开文档只保留方法和限制。

## 记录与恢复

- 每个账号一个子 agent、一个 `runs/<task-id>/`、一份 `evidence.json`；汇总时按 `account_alias` 分组。
- 交接写清：每条通道停在哪、哪个账号已登录、哪边有未提交的测验、下一步先动哪边。
- 恢复时先各读一次页面标题和登录页，再决定从哪边续；一个账号异常时先停两边再排查。
